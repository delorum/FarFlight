# Правила работы над проектом

После каждой доработки:

1. Проверь, нужен ли рефакторинг затронутого кода. Выполни его, если он необходим для ясности, устранения дублирования или поддержки изменений.
2. Проверь влияние изменений на производительность, особенно вычисления на каждом кадре, генерацию мира и отрисовку карты. При необходимости выполни оптимизацию; для потенциально тяжёлых изменений подтверди результат измерениями.
3. Выполни проверки и тесты, соответствующие изменениям.
4. Перед каждым коммитом и последующим push повысь версию в `project.godot` по масштабу доработки. Формат — `0.MINOR.PATCH`: для значимых новых возможностей или крупных изменений механики повышай среднюю часть `MINOR` и сбрасывай `PATCH` в ноль; для небольших доработок, исправлений и изменений документации повышай последнюю часть `PATCH`. Например: `0.11.2 → 0.12.0` для крупной доработки, `0.11.2 → 0.11.3` для небольшой. Каждый коммит должен повышать версию; соблюдай те же правила в README.
5. Создай коммит с понятным и подробным сообщением: что изменилось, зачем и как проверено.
6. Выполни push в GitHub в текущую рабочую ветку. Дополнительного подтверждения пользователя для коммита и push не требуется. Если операция не удалась, сообщи об этом и укажи причину.

Эти действия входят в завершение каждой доработки, если пользователь явно не попросил иной порядок или не запретил коммит либо push.
